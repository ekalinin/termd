# Design

## Context

See proposal.md - Why for the motivation.

State of the code that shapes the approach:

- `render.Render(src, Options)` (`internal/render/render.go`) is a pure function: it takes the document and `Options{Width, Style, Theme}` and returns the terminal output as a string. It does not touch the terminal.
- The CLI sets `Styled: e.stdoutTTY` (`cmd/termd/main.go`), so `termd` writes plain text into a pipe. `--hyperlinks=always` forces hyperlinks, but nothing forces styles.
- The escape sequences termd emits all come from `internal/style/style.go` and form a closed set. A scan of every styled golden file found only SGR `0`, `1`, `2`, `3`, `4`, `9`, `34`, `36`, `38;2;R;G;B`, `38;5;N` and their combinations, and OSC 8 terminated by `ESC \`. mermaid-ascii output reaches the page as plain text.
- `text.Width` (`internal/text/text.go`) measures grapheme clusters with uniseg; every width decision in termd goes through it.
- `highlight.Dark` and `highlight.Light` (`internal/highlight/highlight.go`) only change the 24-bit colors of highlighted code.
- A LR flowchart that does not fit the width is rendered again top-to-bottom by the diagram adapter.
- The repository has no `.github/` directory. `go.mod` requires Go 1.27. `make fmt-check` checks only `cmd` and `internal`.

## Goals / Non-Goals

**Goals:**
- The text of every example on the page is exactly what `render.Render` returns for the same document, width and style options; only the encoding changes from ANSI to HTML.
- Column alignment of wide characters does not depend on the browser font.
- Building the site needs only the Go toolchain.
- The page works without JavaScript.

**Non-Goals:**
- A general ANSI-to-HTML converter. The converter supports only the sequences the generator's own options produce.
- Showing the 256-color mode, the pager or the OSC 11 background detection.
- Matching the look of a particular terminal emulator.

## Decisions

### The generator calls render.Render in-process
A Go program in the same module calls `render.Render` with `Style{Styled: true, Hyperlinks: true, Depth: TrueColor}`, a width of 40, 60 or 80, and a `Theme` function that returns `highlight.Dark` or `highlight.Light`. The packages under `internal/` are importable from inside the module and do not change.
Alternatives: a `--color=always` CLI flag (a product change with its own spec change, out of scope); running the CLI under a pseudo-terminal with `script` (fragile, output depends on the host).

### ANSI to HTML for termd's escape set
The converter walks the rendered string and turns:
- SGR `1`, `2`, `3`, `4`, `9` into CSS classes for bold, faint, italic, underline and strikethrough;
- basic colors (`30`-`37`, `90`-`97`; termd uses `34` and `36`) into CSS variables, so each page theme sets their values;
- `38;2;R;G;B` into an inline `color`;
- `0` into closing the open span;
- OSC 8 open and close into `<a href="...">` and `</a>`.

Text and attribute values are HTML-escaped. An escape sequence outside this set is an error, so a new style in termd fails the site build instead of leaking raw escapes onto the page.
Alternatives: xterm.js (a JavaScript dependency with its own width table, not termd's); screenshots (text is not selectable and has to be regenerated by hand); an HTML backend at the span level inside `internal/render` (needs the rendered lines exported, a change to the renderer).

### Wide grapheme clusters are pinned to two columns
The converter splits text into grapheme clusters with uniseg and measures each with `text.Width`. A cluster of width 2 is wrapped in a span with `display: inline-block; width: 2ch`. The browser then places the next character where termd expects it, whatever advance the font gives the glyph. The page and the terminal use one width model.

### Page assembly with html/template
One template produces `index.html` with a fixed composition: the project name, a one-line description, the install command, a link to the repository, the examples and a footer. The converter output is inserted as `template.HTML`. A caption for an example is written inside the example's markdown, so termd renders it as part of the output. The template, the CSS and the example documents are embedded into the generator with `embed`; the only argument is the output directory.

### Width switcher with radio inputs
Each example is rendered at 40, 60 and 80 columns into three `<pre>` fragments. One group of radio inputs, in a row above the examples next to the theme switcher, selects the width for all examples at once; CSS shows the fragments that match the checked input. 80 is checked by default: it is the width termd uses when it does not write to a terminal. The row stays at the top of the screen while the page scrolls (`position: sticky`). A block wider than the screen scrolls horizontally (`overflow-x: auto`), as a wide block does in `less -S`.
Alternative: a switcher per example (five groups of buttons on the page).

Each rendering is shown in a window exactly as wide as the chosen number of columns (`calc(cols * 1ch + padding)`), with a column ruler (`----+----1----+----2`) above the output and the command that produces it (`termd --width 80 table.md`, plus `--theme` for the code example) in the title bar. Switching the width visibly resizes the windows, and a block wider than the width runs past the ruler.

### Theme: prefers-color-scheme plus a manual switch
Page and terminal colors are CSS variables whose values hold a light and a dark color (`light-dark()`); the `color-scheme` property selects one. Radio inputs `auto` (checked by default), `light` and `dark`: with `auto`, `color-scheme: light dark` follows the system preference; `light` and `dark` set `color-scheme` through `:has(...:checked)`. The code example is rendered with both termd themes, and the same rules select which fragment is visible. The choice is not saved across page loads.

### Code location
The converter and the page assembly live under `internal/`, the entry point under `cmd/`. The existing `fmt-check`, `vet` and `test` targets then cover the generator without Makefile changes to the checks. The converter has golden tests, like the other output-producing packages. A Makefile target builds the site into a git-ignored directory for local preview.
Alternative: a separate top-level `site/` directory with its own `main` package (requires extending `fmt-check`).

### Deployment with GitHub Actions
A workflow runs on every push to `main`: checkout, `setup-go` with the version from `go.mod`, the generator into an output directory, `upload-pages-artifact`, `deploy-pages`. Permissions are `contents: read`, `pages: write`, `id-token: write`; a concurrency group lets only one deployment run at a time. The workflow does not run the test suite; that belongs to the PR testing flow.
Alternatives: HTML committed to a `docs/` folder and checked by a golden test (generated HTML in git and noisy diffs whenever highlighting changes); a `gh-pages` branch (same drift problem without a check).

## Risks / Trade-offs

- [Box-drawing glyphs are taller than a line at `line-height: 1` and draw over the text of neighbouring lines; with `line-height: normal` a line with an emoji is taller than the others and table lines get gaps] → terminal blocks use a fixed `line-height: 1.2`; checked in Chrome at 1x and 2x scale, to be checked in a second browser.
- [A font without a glyph for a ZWJ emoji sequence draws several glyphs that overflow the 2ch box] → the alignment of the following text is kept by the fixed box; the examples use emoji that common system fonts support, checked visually.
- [The flowchart example does not switch from LR to top-to-bottom within 40-80 columns] → pick the example so it does, and check the generated fragments at 40 and 80.
- [The page shows the behavior of `main`, which may be ahead of the installed version] → accepted until the release flow exists; then the trigger moves to tags.
- [Browsers without `:has()` ignore the manual theme switch] → `prefers-color-scheme` still selects a theme.
- [80 columns do not fit a phone screen] → the block scrolls horizontally.

## Migration Plan

1. Before the first deployment, set Settings -> Pages -> Source to "GitHub Actions" in the repository (manual, once).
2. Merge the change; the push to `main` builds and deploys the site.
3. Fill in the repository's Homepage field with the site URL.

Rollback: disable Pages or remove the workflow. termd itself is not affected.

## Open Questions

- The monospace font stack and the values of the basic ANSI colors in each theme, chosen while checking the page visually.
